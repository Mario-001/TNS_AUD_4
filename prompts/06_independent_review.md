# Independent review

Context: SPECIFICATION.md, relevant source and the generated tests.

> Review these tests as proposed code. For every issue identify the exact assertion
> or missing scenario, the requirement at risk and a concrete faulty implementation
> that could still pass. Separate syntax/setup problems from weak test design.
> Check whether the system under test is accidentally mocked, whether expected
> results copy production logic, whether deep mocks hide invalid calls, and whether
> integration tests exercise real persistence. Propose a minimal correction.
> Do not rewrite production code, disable tests or lower expected values. State
> uncertainties and remaining risks. Review comments are hypotheses to verify.
